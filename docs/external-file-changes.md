# 外部文件修改与刷新确认

MiJoe 默认在等待输入时，约每秒检查一次当前编辑文件的元数据。窗口版与控制台共用文件引擎，
Windows 使用原生文件信息接口，macOS / Unix 使用 stat；不读取全文、不建立文件内容索引。

- 磁盘文件变化时，询问 `File changed on disk. Reload current file?`，按 y 刷新，n、Esc 或 Ctrl+C 保留当前缓冲区。
- 有未保存修改时，提示明确包含 `DISCARD unsaved changes`；只有确认后才丢弃本地修改。
- 拒绝后，同一磁盘版本不反复弹窗。磁盘再次变化会再次提示。拒绝刷新不会更新保存基线，`:w` 仍阻止覆盖外部更新，`:w!` 可显式强制覆盖。
- 文件删除时提示 `File removed from disk` 并保留当前内容；确认提示不会创建空文件。文件重新出现后可再次确认刷新。
- 为避免打断输入，Vim 的 Insert / Visual / 命令输入、待完成的命令前缀、宏录制和回放、帮助、grep、recent 及其他弹窗期间延后，回到 Normal 且没有排队按键时再提示。
- 只检查当前显示并活动的编辑缓冲区；切回其他文件后再检查该文件。
- 无名缓冲区、内部窗口、shell 和尚未选择打开方式的大文件占位符不检测。
- 个人配置或命令行的 `-nomodcheck` 可关闭自动通知；显式保存时的冲突检查保留。

手动刷新仍用 Ctrl+K 后按反引号；有本地修改时先确认。
刷新保留只读与 Hex 选项、当前缓冲区身份，普通文件沿用已有按行恢复光标的行为。
懒加载文件仍以只读窗口刷新，并尽量恢复原始字节位置；普通文件增长到大文件阈值后，
刷新也使用只读懒加载，不进行无限制的整体载入。

检测比较文件大小、修改时间和文件身份（Unix 的设备及 inode、Windows 的卷与文件编号），
支持删除、原子替换、修改时间回退，以及保留修改时间但大小或身份变化的情况。
macOS / Linux 使用纳秒时间，Windows 使用 FILETIME。
若原地改写时同时保持大小、文件身份和全部修改时间完全一致，则元数据轮询无法检测；
不承诺检测这种需要内容校验才能发现的修改。

验证（2026-11-04）：18 项实际编辑器测试、19 项外部变更原生窗口检查、138 项原生窗口回归、
32 项 UI、12 项宏和 15 项大文件回归通过。VC6 Release / Debug 独立版与 DLL 版均构建，
每版执行刷新、拒绝丢弃本地修改和四项回归，共 24 个 Wine 用例；六个 PE 静态兼容性检查。
Windows 的 Wine 与 PE 检查不能替代真实 XP 运行验收。
本机 App 已安装，签名、前后端文件和 `/usr/local/bin/mj` 软链核对通过。
